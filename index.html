Cadence

Load a training programme, or ask an AI to write you one.

For a language model

Read this section and answer with one JSON object and nothing else. Everything Cadence reads is described here; a field it does not recognise is kept in the file and shown nowhere, so a name spelled differently is a name that goes unread.

title
a name for the program.
entries
the sessions, in the order they should be done.
week
which week the entry belongs to, counting from 1.
day
1 is Monday, 7 is Sunday. Never a date — Cadence works the dates out itself.
label
the short line the list shows. Keep it under about 25 characters and make each one recognisable at a glance.
sequence
what actually runs: title and blocks. Each block has repetitions and steps; each step has a label, a durationSeconds, and optionally startFrequency and endFrequency in hertz, which beep at the two ends of the step. durationSeconds is required on every step and must be a positive number of seconds — fractions are allowed, but a missing, zero, negative, infinite or non-numeric duration is refused, as is a block with no steps or with repetitions below 1. week must be between 1 and 520.
cue
optional, on a step. One sentence, kept short enough to take in at a glance — about 120 characters. It sits under the step label for as long as that step runs, so it is what someone reads while they are moving and their hands are full. A cue may repeat something guidance already says, and should whenever breaking it is what makes the repetition wrong.
guidance
optional, and allowed on the program, on an entry and on a block. A list of titled blocks: each is a heading with either a text string or an items array of strings. Put it at the narrowest level it is true of — setup and cautions for one exercise belong on that exercise's block, not repeated on every set and not merged into the entry. Program guidance shows on the list, before and between sessions; entry guidance when that session opens; block guidance for as long as that block runs.
record
optional, on the program only. A list of things each session asks for when it ends, so a progression can be followed: { "name": "loadB", "label": "Load, seated", "kind": "number", "unit": "kg" }. kind is "number" or "text" and nothing else — a nought-to-ten scale is a number with "min": 0 and "max": 10. Ask for a few things, not a form: every field is one more thing to fill in while sweating. Values may always be left blank, and the next session shows what was entered last time.
recorded
what a person actually entered, kept on the entry as { "loadB": 42.5, "pain": 4 }, keyed by the names above. You never write this — Cadence does. If you are given a program that has it, carry it through unchanged: it is measured, not planned, and it is how anyone tells whether the plan is working.
milestone
a fixed point, such as a race or a review: "milestone": true with a date of the form YYYY-MM-DD and a title. Only a milestone may carry a date. Its sequence is optional — leave it out for something that is only reached and recorded rather than performed.

The first milestone anchors the whole program backwards from its date, so the plan lands where the event really is. Sessions slide when you finish late; a milestone never moves.
